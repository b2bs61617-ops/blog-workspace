# 公開スキル

「公開して」と言われたら以下を実行する:

0. **タイトルに「【未】」が含まれる下書きは対象から除外する**(2026-09-23にユーザー指示)。「まとめて公開して」のような一括指定の際も、【未】付きの記事だけは公開せず下書きのまま残し、除外した旨をユーザーに報告する。本文が完成しているように見えても、【未】は「要確認」の目印として使われているため、勝手に公開しない。
   - Why: 2026-09-23、chomoand-4.blog(トラジャ)の下書き一括公開で【未】付きの記事(オーダーネックレス記事)を確認せず公開してしまい、ユーザーから訂正・下書き差し戻しの指示があった。
   - How to apply: 一括公開の指示が来たら、対象記事のタイトルを先に一覧表示し、【未】が含まれるものは除外リストとして分けてから残りを公開する。

0.5. **chomoand-1.com(コイキーズブログ)は公開前に`python tools/check_ko1keyz_title.py {公開する記事ID...}`を実行する**(3言語セットなら3件とも、2026-10-24〜ユーザー指示)。タイトルに「KO1KEYZ」が無い記事があれば公開せず、タイトルを「【KO1KEYZ】RYOGAの〜」の形に直してから公開する(タイトルの付け直しはこのスキル経由の更新として確認不要。直したことは報告に含める)。

1. 対象の記事IDを確認する(直前の作業の記事ID、または指定された記事ID)
   - **chomoand-1.com(コイキーズブログ)は、日本語版・韓国語版・英語版の3言語セットをまとめて公開する**(2026-09-06にトモキ確認)。日本語版の記事IDが対象なら、Polylangの`translations`フィールド(または`-kr`/`-en`のslug命名規則)から韓国語版・英語版の下書きIDも引き、3件とも`publish`にする。翻訳版がまだ下書きとして存在しない場合はその言語はスキップしてよい(後日STEP6/7で生成された時点で別途公開する)。chomoand.com・chomoand-0.comは多言語展開していないので対象の1件だけ。
2. [docs/wordpress.md](../../../docs/wordpress.md)の接続情報でREST APIを叩き、ステータスを`publish`に変更(3言語セットなら各IDについて実行)
   - エンドポイント: `POST {サイトURL}/wp-json/wp/v2/posts/{記事ID}`
   - ボディ: `{ "status": "publish" }`
3. 公開後のURL(`{サイトURL}/?p={記事ID}`)を確定する(3言語セットなら3URLとも)
4. **公開したURLすべて**(3言語セットなら日本語・韓国語・英語の3URLとも)について`python tools/google_indexing.py {公開URL}`を実行し、Google Indexing APIへ即時インデックス登録をリクエストする
   - `.env`の`GOOGLE_INDEXING_CREDENTIALS_PATH`が未設定の場合はスキップされるだけで、公開処理自体は止めない(セットアップ手順は[docs/google-indexing-setup.md](../../../docs/google-indexing-setup.md)参照)
5. **chomoand-1.com(コイキーズブログ)の記事のみ**、`python tools/naver_indexnow.py {公開URL}`も実行し、IndexNowプロトコル経由でNaverへ即時インデックス登録をリクエストする(2026-08-02〜)
   - **判定はサイト単位であって言語単位ではない。** chomoand-1.comの記事なら日本語版・韓国語版・英語版の**全URL**をNaverに送る(韓国語版だけではない)。日本語・英語URLを送ってもNaver側がクロール要否を判断するだけで害はない。
   - `.env`の`NAVER_INDEXNOW_KEY`が未設定の場合はスキップされるだけで、公開処理自体は止めない(セットアップ手順は[docs/naver-search-advisor-setup.md](../../../docs/naver-search-advisor-setup.md)参照)
   - chomoand.com・chomoand-0.comの記事にはこのSTEPは適用しない(Naverキー検証ファイルはchomoand-1.com直下にのみ置く運用のため)
6. **Xへの自動投稿(2026-09-23〜、Buffer経由で再開)**。旧`tools/x_auto_post.py`(X API直接利用)はPay-Per-Use化によるコスト($0.20/URL付き投稿)を理由に2026-08-10に停止したが、Buffer(定額プラン、@chomoand17を全サイト共通で使用)経由の`tools/x_auto_post_buffer.py`に切り替えて再開した(経緯は[docs/x-auto-post-setup.md](../../../docs/x-auto-post-setup.md)参照)。
   - 下記「Xの投稿文の作り方」の型でフック文・ハッシュタグを作文したら、`python tools/x_auto_post_buffer.py --text "{フック文}" --hashtags "{ハッシュタグ}" --post-id {日本語版の記事ID} --url "{公開URL}"` を実行する。site指定は不要(**chomoand-4.blog(トラジャ)も含め全サイト同じ@chomoand17チャンネル**、2026-09-25トモキ確認)
   - **例外: chomoand.comのトレンド記事は`--account trend`を付けて@chomotirendだけに投稿する(2026-10-18〜トモキ指示)**。Threadsには流さない(`--account trend`で自動的にXのみになる)。@chomotirendがBufferに未接続ならX投稿だけスキップされ公開は止まらない。口調は下記「トレンド用(@chomotirend)の口調」に従う
   - **一括公開(2本以上)のときは即時連投しない**。`--due-at "2026-09-26T09:00:00+09:00"`(ISO8601)で予約投稿にし、1〜1.5時間おきにずらす。深夜(0〜7時)は避け、同じメンバー・同じネタの記事は間を空ける(2026-09-25トモキ指示)
   - **予約後に「今すぐ投稿して」と言われたら(特番・イベント直前など、2026-10-03トモキ指示)**、先にBuffer GraphQLの`mutation { deletePost(input: { id: "<post_id>" }) { __typename } }`で予約を消す(X・Threadsの両方の`post_id`、返り値`DeletePostSuccess`を確認)。消し終えてから、同じ文面で`--due-at`なしで投稿し直す。予約を残したままだと同じ投稿が二重に出るので、削除に失敗したら即時投稿はしない。
   - **Bufferの無料プランは予約枠が最大10件**。超えると`Scheduled posts limit reached`で失敗するので、11本目以降は先の予約が投稿されて枠が空いてから入れる(公開処理自体は止めない)
   - **添付画像は記事本文内の画像すべて(アイキャッチは使わない、2026-09-27トモキ指示)**。`--post-id`で本文の`<img>`を自動で抜き出して原寸URLで添付する(Xの上限で先頭4枚まで)。**本文に画像が無い記事は文章のみで投稿**する(アイキャッチで代用しない)。ユーザーにX文面を見せるときは、各投稿に添付される画像の枚数(または「画像なし」)も併記する
   - **Threads(chomoand)にもXと全く同じ内容で自動投稿される**(2026-09-29〜トモキ指示)。同じ`x_auto_post_buffer.py`の1回の呼び出しで、本文・ハッシュタグ・記事内画像・URLリプライ・予約時刻(`--due-at`)・`--draft`がそのままBufferのThreadsチャンネルにも入る。結果JSONの`threads`キーで成否を確認し、報告に含める(Threads側が失敗してもX投稿は成立している)。Threadsに流したくない記事だけ`--no-threads`を付ける
     - **Facebook/Instagramへの投稿はしない**(2026-09-29トモキ指示)。chomoand-1.comのJetpack Socialプラグインは同日に無効化済みで、接続自体は残っている(再開するなら有効化するだけ)。きっかけは2026-09-28の27本一括公開で、Instagramが投稿上限(Application request limit reached)に達して14本失敗したこと。**勝手に再有効化しない**
     - **基本は日本語版だけ**。英語版はSNSに流さない(2026-09-29トモキ指示)。日本語の投稿の`--post-id`と`--url`には必ず日本語版を渡す
     - **例外: KO1KEYZ(chomoand-1.com)は韓国語版もXに投稿する(2026-10-18〜トモキ指示)**。Xで韓国語のKO1KEYZ投稿が増えているため。日本語の投稿とは**別の投稿**にする(日韓を1投稿に混ぜると重み280を超える)。日本語の投稿の直後に `python tools/x_auto_post_buffer.py --text "{韓国語フック文}" --hashtags "{韓国語タグ}" --post-id {日本語版の記事ID} --url "{韓国語版の公開URL}" --no-threads` を実行する(画像は日本語版の本文から取る。Threadsには流さず日本語版だけ)。韓国語版の下書きが無い記事は韓国語の投稿もしない。予約投稿にする場合は日本語の投稿と同じ時刻か数分後にする。書き方は下記「KO1KEYZの韓国語の投稿」に従う
   - **「Xは下書きだけ」と指示されたら`--draft`を付ける**(2026-09-28〜)。Bufferの下書きに保存されるだけで投稿・予約はされない(返り値`status: draft`、予約枠10件も消費しない)。トモキがBuffer画面で確認してから投稿する
   - フック文にはURLを含めない(`--url`の内容が2件目のリプライとして自動投稿される)
   - `.env`の`BUFFER_ACCESS_TOKEN`/`BUFFER_X_CHANNEL_ID`が未設定の場合は投稿だけスキップし、公開処理自体は止めない(Google Indexing/Naver IndexNowと同じフェイルセーフ方式)
   - 成功すると`tweet_url`(1件目のツイートURL)がJSONで返るので、結果報告に使う
7. 公開後のURL・インデックス登録の結果・Xへの投稿結果(ツイートURL)をユーザーに表示する

## Xの投稿文の作り方

記事タイプに応じて以下のパターンを使い分ける(2026-08-09、SNS拡散調査の結果を反映)。

| 記事タイプ | フック文の型 | ハッシュタグ | 備考 |
|---|---|---|---|
| 新シーズン・出演者発表速報(koi-real) | 「【〇〇編】メンバー解禁!」+一行の煽り | 番組全体タグ+シーズン限定タグの2〜4個 | 速報性が命。同じ告知を数日おきに再投稿するのも有効 |
| 個人プロフィール・wiki(wiki-article/gakureki-kazoku-kanojo) | 記事タイトルをほぼそのまま流用した疑問形 | 人物・番組タグ中心に2〜3個 | 単発投稿でよい |
| 私服・ブランド特定 | 「これ気になった人いる?」等の問いかけ | ブランド・番組タグ | 画像は該当シーンの切り抜きを使う |
| 歴代まとめ・保存版(teiban-navi型) | 「歴代〇〇一覧」の網羅性を煽る一言 | 汎用タグ中心 | 資産コンテンツなので数ヶ月おきに同じ記事をリバイバル投稿してよい |
| ネタバレ・あらすじ | 「〇〇に大事件?」等の煽り一行 | 番組全体タグ+話数/エピソードタグ | 放送直後〜翌朝に投稿、連投もあり |

| トラジャ(chomoand-4.blog) | 私物特定なら「気になった人いる?」、経歴・予想系はタイトル流用の疑問形 | `#TravisJapan`+登場メンバーの名前タグ(例`#宮近海斗`)、足りなければ`#トラジャ` | 2026-09-25〜。メンバー名は本名=活動名なのでそのまま |
| キテレツ(chomoand-5.site) | トラジャと同じ(私物特定なら「気になった人いる?」、経歴・予想系はタイトル流用の疑問形) | `#KEYTOLIT`+登場メンバーの名前タグ(例`#猪狩蒼弥`)、足りなければ`#キテレツ` | 2026-10-17〜。X/Threadsは他サイトと同じ@chomoand17 |
| Snow Man(chomoand-2.com) | トラジャと同じ(私物特定なら「気になった人いる?」、経歴・予想系はタイトル流用の疑問形) | `#SnowMan`+登場メンバーの名前タグ(例`#目黒蓮`)、足りなければ`#すの担` | 2026-10-18〜。X/Threadsは他サイトと同じ@chomoand17 |

いずれも本文は結論・フックを冒頭2行以内に収め、ハッシュタグは2〜4個(多すぎるとスパム的に見える)。

**トレンド用(@chomotirend、chomoand.com)の口調(2026-10-18〜、2026-10-19更新トモキ指示)**: 女性ファン口調にはしない(くん付けもしない)。ただし落ち着いた事務的な文ではなく、**楽しそうで、読者が「え、どういうこと？」と続きを読みたくなる緊迫感のある文**にする。
- 1行目でいちばん気になる疑問・意外な事実をぶつける(「【速報】」「え、あの映像って…」「まさかの〇〇」「Xが騒然」など)。答えは全部言わず、記事で回収する
- 短い文で畳みかけ、「！」「…」や絵文字(1〜3個、🚨⚡😱🔥👀など)で勢いを出す
- 締めは「真相はこちら👇」「〇〇の理由がヤバい」のように記事へ誘導する
- 煽りすぎて事実と違う書き方にはしない(予測なら予測と分かる言い方に)

例(テレビミセスGOOD DAY記事):
```
【テレビミセス】GOOD DAYで大森元貴が腰を押さえてる…😱
副音声は3人ずっと「腰大丈夫かー！」
実はあの映像、"あの時期"のものだった…！真相はこちら👇
#テレビミセス #MrsGREENAPPLE #大森元貴
```
文字数・ハッシュタグ(本名併記含む)・記事内画像のルールは下と同じ。以下の女性ファン口調と書き出しルールは@chomoand17(トラジャ・キテレツ・Snow Man・KO1KEYZ等)用。

**口調は「女性ファンが自分で呟いている」風にする(2026-09-25にトモキ指示)。** 「〜すぎて無理😭💕」「待って、」「ねぇ〜な人いない？👀」「まとめたよ〜🫶✨」のような話し言葉・共感・問いかけにし、絵文字は1行に1〜3個とたっぷり使う。メンバーは「YURAくん」「KEITOくん」のようにくん付け。宣伝っぽい事務的な文は避ける。文字数は重み280(日本語・絵文字=2、ASCII=1)が上限で、超えると`x_auto_post_buffer.py`が本文を切り詰めるため、本文は約115文字以内に収めてハッシュタグまで確実に入るようにする。

**書き出しは毎回変える(2026-10-06トモキ指示)。** 「待って、」「ねぇ、」で始まる投稿が多すぎたので、この2つは数本に1回まで、連続では使わない。まとめて投稿するときは全部ちがう書き出しにし、直近の投稿とも同じ書き出しを続けない。書き出しの例:
- 感嘆・リアクション: 「え、」「は？」「やばい、」「ちょっと聞いて😭」「無理すぎる…」「泣いた😭」「心臓もたない🫠」
- 報告・自慢: 「速報🚨」「朗報すぎる💐」「ついに〜！」「〜行ってきた！」「〜見つけちゃった👀」
- 問いかけ: 「〜って知ってた？」「〜見た人いる？」「みんな〜どうする？」「〜派？〜派？」
- 結論から: 「〜が可愛すぎる件」「〜確定です🫶」「〜って最高じゃない？」
- 前置きなしで本題から: 「HMV渋谷にKO1KEYZのパネルが12人…😭」

例(YURA記事):
```
YURAくんの育ちの良さ、バレ始めてる…🥺💐
苦手な食べ物も「僕のお口には合わなそう」って断るの、上品すぎて心臓もたない😭💕
神対応エピソード5つまとめたよ🫶✨
#KO1KEYZ #YURA #安部結蘭
```

KO1KEYZ記事でステージネームのタグ(例:#ISSA)を使うときは本名タグ(例:#柳谷伊冴)も併記する。

**Why:** 以前はGoogle Search ConsoleへのAPI連携が複雑なためユーザーが手動でURL登録していたが、2026-07-09にIndexing API経由での自動化に変更した。Indexing APIは本来Job Posting/BroadcastEvent専用と規約上明記されているが、ブログ記事への利用は黙認されている状態であることをユーザーが承知の上で選択している([docs/google-indexing-setup.md](../../../docs/google-indexing-setup.md)参照)。

**How to apply:** 「公開して」「公開する」「アップ(公開)して」などの発言をトリガーとして実行する。記事の削除は絶対に行わない([docs/wordpress.md](../../../docs/wordpress.md))。
