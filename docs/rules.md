# 記事作成の基本ルール

## 記事作成方針(最重要)

トレンドブログの記事は「人の疑問に答える」ことを最優先に書く。人は何かを検索するとき必ず「疑問」を持って検索している。その疑問に正面から答える記事こそが価値を持ち、検索流入につながる。

- タイトルは疑問形・または疑問に答える形にする(例:「〇〇とは?」「〇〇の理由を解説」「〇〇はどうなった?」)
- 記事の冒頭でその疑問に端的に答える(結論ファースト)
- 本文は疑問の答えを深掘りする構成にする
- 情報の羅列ではなく、読者の疑問を解消することを意識する

## 記事投稿時のセット項目

タイトル・本文・アイキャッチ画像・スラッグをセットで作成・投稿する。

- スラッグはタイトルをアルファベット(ローマ字 or 英訳)に変換して設定する(例:「下妻市長 自殺 理由」→ `shimotsuma-mayor-suicide-reason`)。デフォルトのスラッグは日本語になってしまうため、WordPress REST APIの`slug`フィールドに必ず英字スラッグを含める。
- 手順の詳細は[blog-uploadスキル](../.claude/skills/blog-upload/SKILL.md)を参照。

## 記事の質(濃く・詳しく書く)

薄い記事は価値が低い。1記事あたりの情報量を最大化する。

- 文字数は最低でも2,500字以上を目指す(理想は3,500〜5,000字)
- 各H3セクションに十分な説明・エピソード・補足情報を入れる
- 「不明」「確認できていません」だけで終わらせず、周辺情報・推察・SNSの声・関連エピソードを膨らませる([sns-researchスキル](../.claude/skills/sns-research/SKILL.md)で情報を掘る)
- プロフィール表に続いて「性格」「好きなもの」「エピソード」なども積極的に加える
- 経歴は1行にまとめず、各ステップに背景・結果・視聴者の反応を添える
- SWELLブロック(capbox・マーカー・インデントボックス・ボーダーリスト)をフル活用する
- 学校・番組・グループには「どんな〇〇か?」補足ブロックを必ず入れる

## 地図埋め込み(必須ルール)

学校・出身地・職場・観光地・店舗など、**場所が特定できていれば必ずGoogleマップを埋め込む**。「わかっていれば必ず」がルール。

```html
<iframe
  src="https://maps.google.com/maps?q=場所名&t=&z=14&ie=UTF8&iwloc=&output=embed"
  width="100%" height="350" frameborder="0" scrolling="no"
  style="border:0;" loading="lazy">
</iframe>
```

- `q=`に学校名・施設名・住所などを入れる。`z=14`が目安のズーム(最寄り駅と施設の両方が見える距離感)。
- 地図は「どんな学校?」capboxブロックの直後か、H3セクションの末尾に配置するのが自然。
- 適用場面: 出身高校・中学・小学校、アルバイト先・活動拠点、出身市区町村、番組ロケ地(公開されている場合)など。

## 文体ルール

- 句点(。)で文が終わったら必ず`<br>`で改行を入れる。
  ```html
  <p>文章A。<br>
  文章B。<br>
  文章C。</p>
  ```
  記事HTML生成時・文書作成時すべてに適用する。既存記事の修正時も同様。

## サイトマップの既知の問題

サイトマッププラグインが2個入っていて競合していたことがある(削除対応済み)。作業時はプラグインが1個だけになっているか確認する。
