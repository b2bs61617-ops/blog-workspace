# 記事ルールの短い表(サブエージェント用)

[docs/rules.md](rules.md) の大事なところだけを抜き出した表。サブエージェント(article-writer / article-checker)は、まずこれを読む。
細かい型(色コード・HTMLの書き方など)が必要になったら、rules.md の該当する節だけを `grep -n` で探して読む(全部は読まない)。
**rules.md にルールを足したら、大事なものはこの表にも1行足す。** 食いちがったら rules.md が正しい。

## 0. 機械が止めてくれるもの(書くときは意識だけ)
投稿前に `tools/fact_check.py`・`honorific.py`・`easy_read.py` がNGにする。書き方は下のとおり。
- さん付け: 本文の人名に「さん」。タイトル・見出し・表・まとめ枠・わかること枠には付けない。グループ名には付けない
- スマホ向け: 1文60字(80字超はNG)、1段落3文(5文・250字超はNG)、表は3列まで、難しい漢字はかな、硬い言葉は言い換え
- まとめの枠のあとに、枠の外の `<p>` でファン目線の一言感想(「〜してみてはいかがでしょうか！」など)
- `---` / `<hr>` は書かない
- タイトル35字以内・最後は全角「？」「！」・タイトルの数字は本文にもある
- 本文に「マツ」を出さない(「調べたところ」「このブログでは」とぼかす)
- Xの写真を本文に1枚以上(アイキャッチは数えない)
- 日付・曜日・誕生日・メンバーカラーは名簿 `tools/data/members.json`・`events.json` で確かめる(記憶で書かない)

## 1. タイトル
- 読者の疑問に答える形(「〇〇はどこ？」「〇〇の理由は？」)
- 下書きは先頭に【未】(blogkit が自動で付ける。35字は【未】を除いて数える)
- YouTube動画発は動画タイトルの【】の中をそのまま頭に、テレビ番組発は【番組名】を頭に
- KO1KEYZは必ず「KO1KEYZ」を入れる(「【KO1KEYZ】RYOGAの〜」)
- 私物特定はシーン(番組名・会場・共演者)を入れて絞る。持ち主を主語に(「Bがかぶってた帽子」)。アクセサリーは「私服」でなく「着用」
- 同じ人物の既存記事のタイトルの型(【〇〇】の有無など)にそろえる
- 公開ずみ記事のタイトル・スラッグは絶対に変えない

## 2. 構成
- 冒頭: ふつうの段落2〜3文で「フック → 太字で結論 → この記事で扱うこと」
- 並び: リード → 基本情報box(線の囲みだけ) → 「この記事でわかること」box(項目名だけ、答えは書かない) → 本文
- 各H2の頭に、その節の答えを先に出す小さいbox
- 見出しに入れた話題は本文で必ず1〜2文以上書く。書けないなら見出しに入れない
- 最低2,500字(理想3,500〜5,000字)。「不明」で終わらせず周辺情報で深める
- 学校・番組・グループには「どんな〇〇？」の補足。場所が分かれば必ずGoogleマップ
- 複数の人物は1人ずつ枠(personbox)、本名・生年月日・出身地などのスペックも入れる。写真も枠の中
- 時系列の出来事が複数あるなら、冒頭に年表の表
- 表は本当に比べるものだけ。単発の事実は地の文で
- 画像はその話題の節の近くに。figcaption は出典URLだけ
- まとめは ✓ の箇条書き枠 → 枠の外に感想 → 一番下に関連記事box
- 関連記事のリンクは2件以上なら枠+箇条書き。リンク文字は「こちら」でなく記事の中身を書く
- 同じ人物の既存記事(wiki・学歴・私物など)を探して必ずリンクする

## 3. 文体
- です・ます調。語尾を段落ごとに変える(「〜そうです」を3回続けない)。砕けすぎもNG
- 「調査の結果」は硬いので「気になって調べてみたら」「実際に見てみると」
- 同じ動画・企画の既存記事と、書き出し・結び文句を使い回さない
- 句点「。」のあとは `<br>` で改行
- 絵文字は使わない(表示されないことがある)
- 専門用語・略語(FC・当落など)は初めて出たときに一言で説明

## 4. SNS・出典の扱い(抜けやすい！)
- 投稿者の名前・@ID は本文にもfigcaptionにも書かない
- 一般人の投稿文をそのまま引用枠に入れない。要点を1〜2文の地の文にまとめ直す(元の投稿の順番をなぞらない)
- 他人の「特定」投稿(特定bot・比較画像)は、画像も内容も「その投稿があったこと」も書かない
- 特定の手柄をファンに譲らない(「ファンが特定」「Xユーザーが指摘」はNG)。ブログの調べとして結論から書く。ただし愛称など「ファン文化そのもの」が主題の記事は例外
- 元ネタ投稿を主語にした値段紹介(「投稿では2万円」)はNG。一般的な相場として書く
- SNSの反応の引用が2つ以上なら枠でまとめる。引用は短く。反応が1件しかないなら「SNSの反応」の節は作らない
- 目撃情報は「見かけたという投稿があった」と事実だけ。裏付けの弱さを何文も書かない
- SNSで集計された数字は「SNSの投稿をもとにした数字」と書き、元投稿のリンクは貼らない。公式でない旨を一言
- 公式YouTubeが元ネタなら、他人のスクショでなく動画からフレームを切り出す
- ファン手作りの一覧画像をそのまま載せない。複数の情報源で確かめて自前の形に作り直す

## 5. 私物・ブランド特定
- 「私物」と断定しない(1カットだけなら「私物かスタイリスト用意かは分からない」と一言。複数の公式出演で着ているなら不要)
- 値段・素材・発売時期・取扱店を調べる。ドル価格は「340ドル(目安で約5万1,000円)」
- 値段のすぐ下に「購入先」(公式ショップ優先、ページが生きているか確かめる)
- 楽天/Amazonで買える商品は blog-upload STEP1.6 でアフィリエイト枠が入る

## 6. 動画・番組発の記事
- 動画の内容まとめだけの記事は価値が低い。主役は「映っているのに説明されていない情報」(服・アクセ・ロケ地・食べ物)
- ドラマのロケ地は、施設公式の写真・看板・休業のお知らせなど一次ソースで照合し、「なぜそこと言えるか」を具体的に書く。一致点が取れないものは「〜とみられます」、特定できない場面は書かない

## 7. プライバシー(必ず守る)
- 未成年・一般人: 学校名を断定しない、出身地は市区町村まで
- 公式クレジットに名前が出ている制作スタッフは実名OK。一般ファンは名前を出さない
- 確かめられないことを事実として書かない

## 8. サイト・グループ別(色や表記はここから rules.md を grep)
- 色: 1人が主役の記事はそのメンバーカラー。トラジャのグループ記事は紫、比較・複数グループ横断はパステルブルー。SixTONESは無彩色で書いて `tools/sixtones_theme.py` で塗る。キテレツはメンバーカラー表あり。→ rules.md「本文中の強調・ボックス装飾ルール」「キテレツ」「SixTONES」「ランキング」の節
- KO1KEYZ: 本文もメンバーは英語表記(RYOGA など)。装飾の色はメンバーカラーとかぶらないウォームグレー `#8a8378`。ハングルの固有名詞は「ハングル(カタカナ読み(日本語訳))」
- KinKi Kids は「DOMOTO(元KinKi Kids)」。STARTOは改名・再編が多いので最新を確かめる
- マーカーは SWELL の `swl-marker mark_◯◯`(赤は無いのでピンク)。強調は1段落1か所まで
